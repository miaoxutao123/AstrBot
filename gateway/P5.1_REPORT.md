# Phase 5.1 Report — Pre-P6 Hardening

## Implemented

- Stabilized transport identity as `family`, `adapter_type`, `adapter_id`, and
  `endpoint_id` across Core, routing, API JSON, adapters, scripts, and tests.
- Added a string-only, automatically namespaced `AdapterSecretStore` with memory
  and versioned AES-GCM encrypted-file backends.
- Split Weixin authentication, session persistence, inbound/outbound conversion,
  and media handling out of its adapter composition layer.
- Completed the pinned Core and community adapter inventories and performed the
  Adapter API v1 pre-freeze review.

## Breaking changes

P5.1 is intentionally a clean pre-v1 break. `EndpointRef.transport` was removed,
and `AdapterDescriptor.id`/`transport` became `adapter_type`/`family`. Wire models,
filters, fixtures, and callers must use the new names; no dual-field alias is
maintained.

## Endpoint identity before/after

Before, `transport` mixed family and platform concepts while `adapter_id` named an
instance. After, an endpoint independently identifies, for example,
`im / telegram / telegram-main / private:123`. Multiple Telegram instances,
different adapter types, and identical endpoint IDs can therefore coexist, and
Router/API filters can match family, type, or instance without reading metadata.

## Secret/state separation

`AdapterStateStore` remains JSON-compatible operational metadata. Static
deployment secrets remain behind `AdapterContext.get_secret()`. Dynamic
credentials now use `context.secrets`, which exposes only the current adapter's
namespace. Persistent secret configuration requires a base64 256-bit key from
`ASTRBOT_GATEWAY_MASTER_KEY`; missing/invalid keys and corrupted ciphertext fail
explicitly, without deletion or plaintext fallback.

## Weixin credential classification

Account ID, selected base URL, and polling cursor are ordinary state. Login token
and per-user context tokens are credentials. Legacy plaintext development state is
migrated by writing and verifying secret values before replacing the ordinary
state. Invalidation deletes both credential keys and ordinary session metadata.

## Weixin internal refactor

`adapter.py` now composes lifecycle, polling, dispatch, capabilities and auth
delegation. `auth.py`, `session.py`, `inbound.py`, `outbound.py`, and `media.py`
own their respective protocol concerns. Existing P5 behavior remains unchanged;
unknown inbound data is still represented as a raw IM segment.

## Migration matrix completion

The matrix now includes all pinned AstrBot Core message adapters, distinguishes QQ
WebSocket/webhook and WeCom variants, marks WebChat `DROP`, and lists Matrix and
VoceChat separately as `COMMUNITY / FUTURE_PORT`. The provenance map also carries
every unmigrated Core source path and target status.

## Tests

Local P5.1 verification passes 95 tests, including secret encryption/failure and
namespace cases, identity/routing cases, fake IM/sensor/robot regressions, all three
real-adapter integration suites, and a Weixin responsibility-split regression.
Ruff format/lint, strict mypy, and pyright also pass.
An offline base-only lock export contains only PyYAML and pycryptodome; FastAPI,
aiohttp, aiocqhttp, python-telegram-bot, and uvicorn remain optional extras.

## CI

Gateway CI continues Quality, Core, API, Adapter Contract, OneBot, Telegram, and
Weixin jobs on Python 3.10 and 3.13. The Core selection now explicitly includes
`tests/secrets`; identity/routing and architecture guards remain in Core. The
remote run is evaluated after this report's commit is pushed.

## Known limitations

- `MediaStore` materializes complete byte strings and is not a streaming interface;
  streaming is a potential v2 extension.
- SQLite state uses a connection per operation, `asyncio.to_thread`, and a global
  async lock; this is accepted for the current single-process scale.
- Encrypted-file secrets do not provide KMS/Vault integration or multi-process
  coordination.
- Weixin outbound operations still require a context token learned from an inbound
  user message, and all three platforms still require authorized real smoke tests.

## Adapter API changes

`EndpointRef`, `AdapterDescriptor`, and `AdapterContext` changed as described
above. Interactive auth remains optional and defaults to `NOT_REQUIRED`; its
challenge fields remain generic (`qr_uri`, `media_id`, `verification_code`, and
`instructions`). No Weixin-specific concept was added to Core.

## P6 readiness

P0 through P5.1 are complete locally. P6 Satori is next only after human review.
Adapter API v1 is **NOT FROZEN** and no P6, MCP, SDK, hardware adapter, or later
roadmap implementation was started in this phase.
